### devel/crush

- Old version: v0.89.0
- New version: v0.92.0
- Upstream: https://github.com/charmbracelet/crush
- Build system: Go modules (lang/go port module), Language: Go
  (go.mod requires go >= 1.26.6; current OpenBSD lang/go is 1.26.7)
- Status: READY_FOR_OPENBSD_TESTING

Changes:
- MODGO_VERSION v0.89.0 -> v0.92.0; dropped REVISION.
- Added MODGO_LDFLAGS version injection:
  `-X github.com/charmbracelet/crush/internal/version.Version=${MODGO_VERSION}`
  (matches upstream goreleaser). Verified locally with
  -buildvcs=false: binary reports `crush version v0.92.0`.
- modules.inc regenerated by replicating OpenBSD's
  modgo-gen-modules-helper (OpenBSD::PortGen::Port::Go) exactly:
  `go list -mod=mod -m all` + `go mod graph` on the proxy .mod file,
  uppercase `!`-escaping, tab alignment. 451 MODGO_MODULES,
  414 MODGO_MODFILES. The same pipeline reproduces the checked-in
  v0.89.0 modules.inc byte-for-byte, so the mechanism is validated.
- distinfo: 1317 files (main zip + zip/mod for MODGO_MODULES + mod for
  MODGO_MODFILES) downloaded from proxy.golang.org, SHA256 (base64,
  OpenBSD format) and SIZE computed. Internal consistency verified:
  no missing, no orphan entries.
- Dependency changes: routine bumps (bubbletea 2.0.8->2.0.9,
  fantasy 0.41.0->0.42.0, x/net 0.57.0->0.58.0, x/text 0.40.0->0.41.0,
  testify 1.11.1->1.12.0, ...); some AWS S3 SDK deps dropped/added.
  No new system dependencies; WANTLIB unchanged (c pthread).
- Portability: internal/clipboard has explicit openbsd build tags
  (golang.design/x/clipboard); internal/dns only affects
  TERMUX/Android; SQLite via modernc.org/sqlite (pure Go).
  Cross-compile for GOOS=openbsd GOARCH=amd64: `go build .` and
  `go build ./...` both succeed with no errors.
- PLIST: unchanged (@bin bin/crush).
- OpenBSD concerns: none found statically. Native test should confirm
  clipboard and terminal behavior.
